=== [Unreleased]

==== Fixed

* **A repository named `../..` is no longer accepted.** The census, the claims
  registry, engineering receipts and the ultraplan each checked `OWNER/REPO`
  with a pattern like `[-\w.]+/[-\w.]+`, which accepts dot segments. A
  github.com link made from such a name resolves, in a browser, to some other
  page. All of them now use one rule, GitHub's own, in `scripts/repo/github.mjs`:
  a login (single hyphens only, none at either end), then a repository name
  that is not dots alone. Every name in the current data passes it.
* **A `CI/gate` publisher may not filter `workflow_run` by branch.**
  GitHub applies `branches` and `branches-ignore` to the triggering run's
  branch, so a filtered publisher never posts the status on a PR head and the
  PR waits for ever. `check-required-contexts.sh` now refuses any such filter
  except `branches: ["**"]`; negative fixtures cover both keys. Ported from
  rsr-template-repo#481.
* The census picked a repository's status document by alphabetical order, so a
  template-era `PROOF-NEEDS.adoc` was chosen over the real ledger beside it.
  `scripts/census/build-rows.sh` now prefers `PROOF-STATUS`, then
  `PROOF-NEEDS`, then `proof-debt`. Rows already committed change only when
  they are rebuilt.
* The `metadatastician/hvn-dehallucinator` row is rebuilt from that
  repository's `main` at `f2f31f7`, 2026-11-09 (16 own proof files, was 9; status
  document `docs/status/PROOF-STATUS.adoc`). The other rows are still the
  2026-10-26 census.

* `repo-init` minting a repository created with GitHub's "Use this
  template" (measured on metadatastician/lintel, 2026-10-14):
** provenance recorded the CHILD's own HEAD as the template commit. The
   commit is now resolved by tree equality against the template's history
   (`scripts/resolve-template-pin.sh`), before anything is written, and an
   unresolvable tree aborts the mint (`RSR_TEMPLATE_URL`,
   `RSR_TEMPLATE_COMMIT`, `RSR_ALLOW_UNPINNED=1` for the exceptions);
** the template's name, owner and deed file are derived from the checkout
   (Justfile, then remote), not hardcoded, so a mint from a minted repo works
   (ported from lintel#9, which did not merge; its removal of the
   `[YOUR-REPO-NAME]` deed seds was not ported, since only they fill it);
** every rewrite pass and completeness check reads one file list: the
   repository's own files (`git ls-files`, plus untracked not-ignored), minus
   `.machine_readable/mint-verbatim.txt`. The strip pass no longer edits
   git-ignored sibling checkouts under `_build/`, nor the fixture tests its
   own leftover check exempts; `strip-instruction-blocks.rs` takes files, not
   a directory. `check-no-placeholders.sh` reads the same manifest;
** a fresh mint of main aborted on `julia_library_test.sh`'s package-UUID
   fixture token; it is now carried verbatim;
** the repository map is generated from the work tree (`gen-repo-map.sh
   --worktree`), after the last tree-changing step, so it no longer lists
   `archetypes/` and the template's deed name;
** stage 8 no longer tells a minted repo to arm `check-variant-drift.sh`,
   which a fresh mint cannot pass (101 rendered files differ); it points at
   `check-template-conformance.sh`. The (variant) clause now declares the
   mint's removals, and the drift gate says why it fails on a minted repo;
** deed-validate.yml's "Copy it from …" line names the template as the
   upstream source, so the self-name pass leaves it alone.
* `tests/e2e/use_template_mint_test.sh` (wired into estate-rules): the first
  CI job to run a full mint, with a negative control beside each check.

==== Added

* **The ultraplan: a tech tree of Mathesis, data first.** `docs/ultraplan/`
  holds three JCS JSON Lines files:
  ** `tree.jsonl`, the nodes, whose needs are the edges;
  ** `advisors.jsonl`, the council;
  ** `expeditions.jsonl`, the return tickets.
+
  `scripts/ultraplan/ultraplan.mjs` generates `generated/ultraplan.adoc` and a
  picture, `generated/tree.svg`. They show the eras, the frontier, the forks,
  the confluences and each advisor's pick (the private me advisor names none), all
  derived and none typed.
+
  The generator refuses:
  ** a done node without evidence that holds: a file that git tracks, a claim
     grade the registry derives, or an accepted ADR. Every file the checks read
     (evidence, refs, ADRs, the registry view and the plan's own sources) is
     one git tracks, at its own path: no link along it, nothing untracked,
     nothing in `.git`, and valid UTF-8 (a malformed byte is an error, never
     a silent U+FFFD). `scripts/repo/files.mjs` reads them, so a clone and
     a linked worktree read the same; An ADR is accepted only when its
     header states `:status: ACCEPTED` and its Status section agrees (owner
     ruling 2026-11-25), each read by `scripts/decisions/adr-status.mjs` so
     that it never finds a status Asciidoctor would not. A record holding an
     inline reference that changes an attribute (`{set:...}`, `{counter:...}`
     or `{counter2:...}`; a counter turns ACCEPTED into ACCEPTEE) has no
     readable header. `just adr-check` reads the records git tracks, each at
     its own path, and fails when `docs/decisions` is a link. A record whose
     status the readers refuse fails the check; only a record that states no
     status at all is listed as unset;
  ** a done node whose needs are not done, and a node still in play that needs
     a dropped node (it could never start);
  ** a cycle;
  ** more than three active nodes;
  ** a ref that does not point at one place: each names a passage that occurs
     exactly once in a file here, a path here, a file of another repository at
     a full commit, or an issue, and never a line number;
  ** a text the page could not show as written: one holding a control
     character, a line or paragraph separator (U+2028, U+2029), a
     bidirectional formatting control, a run of
     spaces, or a space at its start or end. Every text is plain text (owner
     ruling 2026-11-25): the page writes each ASCII punctuation mark in it as a
     character reference, so it shows exactly as written and forms no markup;
  ** any note from the private me advisor.
+
  `just ultraplan` and `just ultraplan-check` run it, and `check-views` includes
  the check. A line not in JCS form is named with the command that writes its
  form; no error message echoes a record. The site copies a view's pictures,
  so the tree's image works there.
* **The site reads nothing from outside the repository.** `scripts/site/site.mjs`
  reads each view, the front page's sources and each asset it copies only as a
  file git tracks, at its own path, and fails the build otherwise. Asciidoctor
  now runs in secure mode, so an `include::` in a view becomes a link, which
  the link check refuses, instead of the included file's text: in safe mode,
  with the base directory at `/`, a view could include any file on the
  system. The output is otherwise byte-identical. A link to a repository file
  becomes a GitHub link only when git tracks the file. The build writes only
  into a fresh output directory (absent, or empty and not a link), so a link
  left in an old output tree cannot make it overwrite a file elsewhere.
  `site-check` now runs the site tests, so CI runs them; it did not before.

==== Changed

* Divergent root/`www/` `.well-known/` content is now quarantined to
  `www/.legacy-well-known-<YYYYMMDD>/` instead of being left in place: the
  estate-wide sweep (#119) is unattended, so a conflict must not halt it, and
  must not be silent either. The `www/` copy is untouched, both hashes are
  printed, and the run exits non-zero. `--in-place` keeps the previous
  contract (preserve both, exit 1) for hand resolution. The quarantine lives
  under `www/` rather than at the root because the root allowlist is matched
  literally and bidirectionally, so a dated root directory would report as
  drift in every repository swept.
