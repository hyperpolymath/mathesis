= Mathesis
:toc: preamble
:icons: font

Mathesis is the maths section of the hyperpolymath estate. It keeps an atlas
of the mathematics in other repositories, the theory that no single system
owns, and methods that apply mathematics to decisions. Each statement carries
its evidence: Mathesis derives status from the receipts of the home
repositories, and does not assert it.

The standards repository prescribes what must be proved
(https://github.com/metadatastician/standards/blob/main/3-practice/PROOF-POLICY.adoc[PROOF-POLICY]).
Each home repository proves its own claims and keeps their receipts. Mathesis
describes what is proved, where, and how strongly.

== What it does

* *A census of proof files.* It reads each public repository in the frame
  (`docs/atlas/census/repos.jsonl`) and records one row of counts for each
  repository that has proof files of its own: provers, declarations, holes,
  axioms. Each row names the commit that the census read and when.
* *Generated atlas views.* A catalogue split into theory and engineering, an
  A-Z view, an organisation view and a machine-readable index, all generated
  from the census rows.
* *A claims registry.* Claim pins point at one theorem in its home repository,
  at a commit and a receipt digest. The canon receipt reader of PROOF-POLICY
  §8.5.1 derives each Proof Witness Grade. No grade is typed by hand.
* *Bridge candidates.* Recorded relations between artefacts in two
  repositories, generated into one view.
* *Home theory.* THY-1, reachability is monotone under additive features, is
  proved in Agda and re-proved in Rocq and Lean. CI checks all three in a
  pinned Guix shell.
* *Applied systems.* Methods that apply mathematics to decisions, starting
  with accounting and finance. Design documents only so far.
* *Privacy by count.* The frame names public repositories only. The number of
  private repositories in the listing is kept as one number.

== Quick start

The views check needs Bun, network access for the receipts, and a checkout of
`metadatastician/standards` at the reader pin named in
`scripts/registry/claims-registry.mjs`.

[source,bash]
----
export MATHESIS_STANDARDS=/path/to/standards
just check-views
bun scripts/atlas/census-atlas.mjs find agda
----

The proof checks need Agda, Rocq and Lean. CI runs them in the pinned Guix
shell; `just check` runs both halves.

[source,bash]
----
guix time-machine -C build/channels.scm -- shell -m build/manifest.scm -- just check
----

Wondering how this works? See link:EXPLAINME.adoc[].

|===
|Path |Purpose

|`docs/atlas/`
|The atlas shelf: census data (`census/`), authored claim pins and bridge

|The census, the atlas views and the claims registry

|`tests/census/`, `tests/atlas/`, `tests/registry/`, `tests/proofs/`
|Their tests, with negative controls

|`verification/proofs/`
|Home theory sources: Agda, Rocq and Lean

|The proof receipt of Mathesis

|`applied-systems/`
|The applied shelf

|`docs/status/`
|Roadmap, proof needs, proof status, readiness and test needs

|`mathesis_chora.deed`
|The repository deed: identity, boundaries, golden path
|===
