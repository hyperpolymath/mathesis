= Mathesis architecture — implemented boundaries
:revdate: 2026-11-01

== Purpose

Mathesis is the estate's mathematical source-discovery and proof-orientation index. It is *not* a theorem prover, a universal proof-status authority, or a replacement for the mathematics in individual repositories. The linked source repository, pinned revision and actual proof checker determine the status of a theorem; Mathesis cannot infer that status from a file count or a passing badge.

== Implemented data flow

[source,text]
----
Repository census input (docs/catalogue/census/repos.json)
  -> scripts/census/ (source and prover-file discovery)
  -> corpus counts, holes/unsafe candidates, reachability observations
  -> docs/catalogue/census/catalogue-rows.json
  -> generated docs/catalogue/catalogue.adoc
  -> scripts/atlas/census-atlas.mjs
  -> docs/atlas/generated/ (A-Z, class, owner; index.json)
  -> lookup and bounded context-pack commands
----

The census counts and classifies observed files. It does not establish that Agda, Rocq, Lean, Idris2, SPARK or other proofs have passed. The atlas is generated from the census rows; it does not invent theorem identities, independent witnesses or semantic equivalences. Private or unreachable sources must not be treated as having no mathematics, and private metadata must not be published.

== Explicitly not implemented by this document

A theorem-level registry with verified cross-prover translations; automatic proof correspondence; causal/semantic identity of theorems across forks; a mandatory database architecture; full-estate incremental rescanning; or an agent write-back system are *not* established merely by this architecture description. They remain independently reviewable proposals requiring evidence and acceptance tests.

== Invariants and failure conditions

* *No source, no theorem certification.* A file containing a prover language is a discovery result, not a successful verification receipt.
* *No authority duplication.* A local Mathesis proposal cannot revise `metadatastician/standards` policy.
* *No invisible drift.* A generated atlas must be reproducible from its indexed census input and named script.
* *No false negatives from inaccessible sources.* Unreachable and private observations remain marked unknown, not empty.
* *No source loss through indexing.* Aggregating counts is a declared lossy view; it must never be mistaken for evidence identifying a particular theorem.
