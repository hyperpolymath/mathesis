= Mathesis discovery atlas — census-backed first slice

This is a *generated, read-only directory of proof-source repositories*, not yet a
complete alphabetic mathematical concept atlas. It derives from
`docs/catalogue/census/catalogue-rows.json` and never alters
or reclassifies the source census. A–Z means repository-name order, not a claim
that these are all the mathematical concepts relevant to the estate.

The first views are A–Z repositories, theory-versus-engineering census class,
and owner/organisation grouping. `index.json` is machine-readable. The CLI
supports source discovery and a bounded context pack suitable for agents.

Run with Bun: `bun scripts/atlas/census-atlas.mjs build`, `check`,
`find idris2` or `context idris2`.

Proof declarations, axioms and holes are *counts found by the original census*.
They are not kernel-check receipts; source files are not included in the
summarised rows, so this atlas must not invent per-theorem names, evidence,
proof status, assumptions, equivalence, or independent verification.
The next slice requires a separately reviewed, source-anchored claims registry;
it is proposed in link:../decisions/0004-claims-registry.adoc[ADR 0004]
(pilot view: link:../registry/registry.adoc[`docs/registry/registry.adoc`]).
No private-source records are added or published by this generator.

== One writer for census data

Census rows change in one way only: `just census` (the whole frame) or
`just update-rows OWNER/REPO...` (named repositories). Both rebuild the
catalogue and this atlas from the same rows. Nobody edits
`catalogue-rows.json`, `unreachable.json` or the generated views by hand.
Only one pull request that changes rows is open at a time; record it under
"Open census work" in link:../status/ROADMAP.adoc[`ROADMAP.adoc`] before it
opens. The deed states the same rule in `(bot-directives (census-writer))`.
Two sessions that refreshed rows at once made the 17 conflicting pull requests
that work order 0.1 of the re-anchoring plan had to triage.
