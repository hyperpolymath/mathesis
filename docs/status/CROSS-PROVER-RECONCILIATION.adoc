= Cross-prover proof reconciliation — working policy
:revdate: 2026-11-05
:toc:

== Scope and authority

This is a *research and verification policy*, not a claim that proofs across
languages have already been reconciled. Mathesis indexes proof evidence and
relationships; it does not become the authoritative proof kernel for its
independent source repositories. ECHIDNA is the intended longer-term
reconciliation automation, not an already complete cross-prover translator.

Maintain a source theorem's statement, premises, universe/type discipline,
prover version, module, revision and proof assumptions before porting it.
Preserve existing Idris2, Coq and Lean gates during migration. If a proof
cannot be translated faithfully, create an independent Agda proof of an
explicitly compared statement. An Agda proof of a *weaker* proposition never
silently replaces the original theorem.

== Canonical Agda gate

Use the documented Agda CLI spelling, with capital K:

[source,shell]
----
agda --safe --without-K --cubical-compatible <Module.agda>
----

Agda's manual specifies `--without-K`; `--cubical-compatible` implies
it but does **not** activate full `--cubical` support. This policy
requires all three flags explicitly at checked entrypoints and CI.
File-level OPTIONS pragmas may reinforce but not replace the command.
Pin/record a compatible Agda and standard-library pair for each corpus.
Imported libraries must satisfy the applicable safe / without-K /
cubical-compatible compatibility requirements. Do not bypass a failing
import with `--allow-unsolved-metas`, `--type-in-type`, `postulate`
or unsafe compiler switches.

A module dependent on genuinely full Cubical Agda must be recorded
as an explicit proof-profile exception for review; do not claim it
passed the default profile. A failed migration remains *unreconciled*,
rather than being hidden, skipped or relabelled `PROVEN`.

In this repo `scripts/check-proofs.sh agda` is the manifest-coverage
hard gate; `just proof-check-agda` invokes it. Its command is the
canonical source for local and CI checks.

== Independent Coq and Lean inspection

Coq and Lean independently check statements or explicitly specified
witness translations where there is a trustworthy conversion. Neither
kernel automatically verifies arbitrary Agda terms, and equal theorem
names do not establish semantic agreement.

For every claimed cross-prover correspondence, record:

* a stable theorem identifier and owning repository;
* the exact *proposition and premises* in each prover (including any
  translation of equality, quotients, guardedness, universe levels,
  modalities, partiality and effects);
* the revision, prover version, library dependencies, build command
  and observed CI/runner result for each;
* whether the relation is `same-statement`, `refinement`,
  `conditional-transport`, `countermodel` or `unassessed`;
* the *bridge justification* (theorem, checked translation or
  explicit semantic comparison) plus any unproved side conditions;
* whether the result is model-level only, runtime-refined or
  externally warranted. A type-checked proof is not independent
  evidence about physical reality.

The strongest possible status requires both a justified correspondence
and independently verified targets; two successful local builds alone
do not satisfy it.

== Status vocabulary (never collapse)

[cols="2,4",options="header"]
|===
|Status |Meaning
|NOT-INVENTORIED |The theorem and exact statement have not been recovered
|INVENTORIED |Original claim, source and dependencies located, without fresh compilation evidence
|AGDA-PENDING |Translation/reproof proposed; full Agda command has not succeeded
|AGDA-VERIFIED |Exact Agda artefact checked with the policy flags at a recorded revision
|COQ-CHECKED |Corresponding Coq module checked, but cross-prover equivalence NOT implied
|LEAN-CHECKED |Corresponding Lean module checked, but cross-prover equivalence NOT implied
|BRIDGE-PENDING |Both sides may compile, but proposition correspondence or side conditions are unproved
|RECONCILED |All stated targets checked and the declared correspondence obligation discharged
|COUNTEREXAMPLE |A soundly evidenced mismatch, inconsistency or refuting instance
|QUARANTINED |Known failure kept visible with issue, reason and a recheck path
|===

A proof can have multiple statuses: a successful independent proof is
not inherently a verified Agda–Lean–Coq bridge. Use separate fields
when publishing a machine-readable register.

These statuses are *correspondence states*. A theorem's *Proof Witness
Grade* (`PWG-3`, `PWG-2i`, `PWG-2ii`, `PWG-1`) is a separate field, derived
from these states and the kernel receipts. Its rules are in
https://github.com/metadatastician/standards/blob/main/3-practice/PROOF-POLICY.adoc#proof-witness-grades[PROOF-POLICY §8].
A recheck leg raises the grade only once it is `RECONCILED`. A
`COQ-CHECKED`, `LEAN-CHECKED` or `BRIDGE-PENDING` leg does not raise it.
Never write a grade into a status field, and never write a status into the
grade field.

Existing proof statuses in these repos are historical evidence, not
automatic proof of compliance with the new mode. Do not make all
repos depend on Mathesis or ECHIDNA to build their local proofs.

== Graduation / rollout

. Update direct Agda entrypoints and CI commands *in each owning repo*.
. Recheck first-party modules and all imported dependencies under the
  new invocation. Record errors without weakening the gate.
. Inventory a theorem and obtain a full-mode Agda receipt.
. Reprove or inspect the corresponding proposition in Lean and Coq.
. Prove/validate the bridge (or label it `BRIDGE-PENDING`).
. Add the receipt and unresolved proof assumptions to the registry.
. Only later automate the reconciliation with ECHIDNA.

The central register below is currently a *todo list*: **no new
full-mode runs or cross-prover reconciliations were observed during
this policy edit**. CI must supply the evidence before any result
is relabelled.

== Catalogued grades (derived, never assigned here)

PROOF-POLICY §8.5: "Mathesis may catalogue grades. It derives them from those
receipts and does not assign them. The home repository owns the theorem and its
evidence." What follows is a catalogue entry only; the authority is
`hyperpolymath/trope-checker`, `docs/status/PROOF-STATUS.adoc`.

As of 2026-11-09, trope-checker carries the estate's first §8.5 PWG record. Both
of its theory groups read `ungraded`, for different reasons, and the distinction
is the useful part:

* *Theorem B* — `ungraded` for want of a *receipt*, not a proof. The flags in
  force already are the §2.1 invocation (`proofs.yml:167`,
  `build/just/proofs.just:87,212` all pass `--cubical-compatible`), but every
  recorded result in that repository is written up as `--safe --without-K` only,
  and §2.1 declassifies prior successes under that profile. A recorded §2.1 run
  at the current commit would move this to `PWG-3` with no proof work at all.
* *The Lean-witnessed results* — `ungraded` for want of an Agda *source* (§8.1).
  The Lean leg is target-only evidence under §3, so `BRIDGE-PENDING`, and the
  Mathlib dependency means it could not count even once an Agda source existed.

Neither can reach `PWG-2i`, `PWG-2ii` or `PWG-1` from where the tree stands: no
Rocq development exists in that repository, so the ladder has a missing rung
independent of any Agda work. This is the first concrete instance of the pattern
this document predicted — a successful independent proof is not a verified
Agda–Lean–Coq bridge.
