=== THY-1: reachability is monotone under additive features

[cols="1,3"]
|===
|Statement
|In a dependency graph whose edges are guarded by features closed under
Horn rules, and by an arbitrary per-target condition, a node unreachable
with every feature requested is unreachable under any request, on each
target (`Cargo.absent-under-all-features`). The general form is
`Monotone.reach-mono`: reachability over a monotone family of edge sets
is monotone.

|Source
|`verification/proofs/agda/FeatureReachability.agda`

|Why
|It justifies the rule in `standards` `docs/UPSTREAM-DEPENDENCY-WATCH.adoc`
to run `cargo tree --target all --workspace --all-features` and read a
missing crate as missing from every build.

|Agda leg
|`PROVEN`. Receipt:

* Checker: Agda 2.6.3, the Ubuntu 24.04 `agda` package that
  `agda-proof-policy.yml` installs.
* Invocation: `agda --safe --without-K --cubical-compatible
  FeatureReachability.agda` from `verification/proofs/agda`; also
  `scripts/check-proofs.sh agda`, which passes.
* Source: `f68b78d6ceb8d3c83f96f5ab8e57779442a8834f`; file SHA-256
  `4e39d6ae751d97d3edf57720ccf844d90de3e9ee6603901a04f5eb6494d94564`.
* Import cone: the module and `Agda.Primitive`, which the prover supplies
  (`agda --dependency-graph`, checked 2026-11-10). The module imports
  nothing, the standard library included, and contains no postulate
  (comment-aware scan). `--safe` refuses postulates. `Agda.Primitive`
  postulates exactly `Level`, `lzero`, `lsuc` and `_⊔_`, each bound by its
  `BUILTIN` pragma: the trusted base the receipt records (§8.4).
* Negative controls, all rejected: a planted postulate, a planted false
  claim, a non-terminating definition, and a `reach-mono` that skips the
  monotonicity step.
* Axioms: none.
* Receipt state: superseded on 2026-11-10 by the CI receipt below.
* CI receipt (current): Agda 2.7.0.1 in the pinned Guix (`8edb9da`), same
  invocation, at commit `336768958d01`, run 42896264290. The file SHA-256 is
  unchanged, and the log reports no postulate in the cone (`Agda.Primitive`,
  `FeatureReachability`).

|Rocq leg
|`PROVEN`, route `re-proved`, correspondence `RECONCILED`. Receipt:

* Checker: Rocq (Coq) 8.18.0, the Ubuntu 24.04 `coq` package.
* Invocation: `coqc FeatureReachability.v` from
  `verification/proofs/coq`; also `scripts/check-proofs.sh coq`, which
  passes.
* Source: `f1be654e69b23873ea40651cb40e0e095ac53680`; file SHA-256
  `e2f90043366fb8061784da4cd12af3278e8a9ea0af78fdba4490f96f28b68cb1`.
* Imports: the prelude only.
* Axioms: `Print Assumptions` reports "Closed under the global context"
  for `absent_under_all_features`, `reach_mono` and `edge_mono`.
* Negative controls: a planted false lemma is rejected. A planted
  `Admitted` compiles, and `Print Assumptions` reports it as an axiom.
* Receipt state: superseded on 2026-11-10 by the CI receipt below.
* CI receipt (current): Rocq 8.18.0 in the pinned Guix (`8edb9da`), same
  invocation, at commit `336768958d01`, run 42896264290. The file SHA-256 is
  unchanged, and `Print Assumptions` reports `absent_under_all_features`
  closed under the global context.

|Lean leg
|`PROVEN`, route `re-proved`, correspondence `RECONCILED`. Receipt:

* Checker: Lean 4.15.0 (`11651562caae`, the version
  `verification/proofs/lean4/lean-toolchain` pins), installed from the
  GitHub release archive (SHA-256
  `af71a2569a9f68337de2434829b3008cd8e32c436e9cb6bd8c84a2c2ba3585c9`)

* Invocation: `lean FeatureReachability.lean` from
  `verification/proofs/lean4`; also `scripts/check-proofs.sh lean4`,
  which passes.
* Source: `f1be654e69b23873ea40651cb40e0e095ac53680`; file SHA-256
  `4158e54f85c8e83e49789869a4e9b12fe4b8d7460981f5c8442479268f17d55a`.
* Imports: none; Lean core only, no Mathlib.
* Axioms: `#print axioms` reports none for `absentUnderAllFeatures`,
  `reachMono` and `onMono`.
* Negative controls: a planted false lemma and a non-terminating
  definition are rejected. A planted `sorry` compiles with a warning, and
  `#print axioms` reports `sorryAx`.
* Receipt state: superseded on 2026-11-10 by the CI receipt below.
* CI receipt (current): Lean 4.29.0 in the pinned Guix (`8edb9da`), same
  invocation, at commit `336768958d01`, run 42896264290. The file SHA-256 is

|Why neither leg is transported
|Lambdapi's Rocq and Lean exports translate before elaboration and drop
rewrite rules (Lambdapi `doc/cli.rst`, `raw_coq`/`raw_lean`). The
Agda2Dedukti encoding of Agda depends on rewrite rules, so the pinned
exporters have no route into either target, and §2 falls back to
re-proof.

|Dedukti check (supplementary)
|`BLOCKED`. It would not count toward the grade in any case; only the
Rocq and Lean legs do (§8).

* Translator: Agda2Dedukti `c7c7d67`, on its Agda fork `to_dk` at
  `b026db1` (Agda 2.6.3 pre-release). Both were built with GHC 9.4.7 and
  a Hackage index pinned to 2022-05-31.
* Build patch: one line in the fork's `Reduce/Fast.hs` (no `MonadFail`
  instance for `ST`), the same fix upstream Agda later made.
* Build check: the build translates all 39 of the translator's own
  mode-1 test files.
* Flags: the fork predates `--cubical-compatible`. The translated copy
  therefore differs from the source only in its `OPTIONS` line, which
  reads `--safe --without-K`.
* Failure: Agda checks that copy, and then translation fails on
  `Monotone.reach-mono` with "Expected a unrestricted argument, but found
  an erased argument". `--no-forcing` does not help.
* Minimal reproducer, seven lines: a function inside a parameterised
  module that matches on an indexed type declared in the same module.
  The same definitions at top level translate.

So no `.dk` file for THY-1 has been checked. Lifting `Monotone` and
`Cargo` to top-level definitions would avoid the limitation, but it
would check a restated copy rather than this file.

|Statement correspondence (§2.2)
|Compared by reading, item by item. Each target restates every Agda
definition with the same parameters, constructors and fields, and states
`reach-mono`, `absent-below` and `absent-under-all-features` with the
same hypotheses and conclusions. The differences are encoding only:

* Agda `Set` is `Type` in both targets, so every relation stays
  proof-relevant. `Ctx : Set₁` is a universe-polymorphic `Type` in Rocq
  and `Type 1` in Lean.
* The empty type: Agda `⊥` is `Bot` (Rocq) or `Empty` (Lean), and
  `¬ A` is `A → Bot` or `A → Empty`.
* Equality: Agda `_≡_` (in `Set`) is `eq` (in `Prop`) in Rocq and `Eq`
  in Lean. It occurs only in the `src` and `dst` fields of `Edge`, which
  no proof inspects.
* `_⊑_` takes the feature implicitly in Agda and Lean, and explicitly
  in Rocq.

Residual assumptions: none in any leg.

|Machine receipt (§8.5.1)
|`verification/receipts/theory_praxis.deed`. The canon reader

(link:../atlas/generated/registry.adoc[`docs/atlas/generated/registry.adoc`]).

|`pwg`
|`1` (since 2026-11-10): `PWG-2ii`, and every counted witness has a current
receipt from one headless, isolated, pinned CI run on the exact source commit
`336768958d01` (PROOF-POLICY §8.2). The grade holds while those receipts stay
current: a later commit that breaks a leg, or a run that cannot be repeated,
drops it (§8.4). Before 2026-11-10 it was `2ii`, because each receipt came
from a local run.

|`foundation_diverse`
|`false`

|Applying it to Cargo
|`ASSUMED`: Cargo's resolver activates exactly the modelled edges.
Features unify by union, no feature removes a dependency, and the version
graph is the one fixed in `Cargo.lock`. Under resolver 2, build and dev
dependency units unify features separately, and the theorem applies to
each unit's graph.
|===

== Applied obligations

=== APP-1 to APP-4: the cohort model of the applied shelf

[cols="1,3"]
|===
|Statements
|`docs/status/PROOF-NEEDS.adoc`, rows APP-1 to APP-4.

|Agda (source of truth)
|`verification/proofs/agda/Applied/`: `Cohort` (the model), `Status` and
`Missing` (APP-1, APP-4), `Cash` (APP-2, APP-3, for any ordered abelian
group), `IntNumber` and `IntLaws` (the integer instance and its laws).
`--safe --without-K --cubical-compatible`; no postulate in any import cone.

|Rocq leg
|`PROVEN`, route `re-proved`. `verification/proofs/coq/Cohort.v`, Rocq
8.18.0. The gate's `Print Assumptions` finds all 82 theorems closed under
the global context. The standard library's `PeanoNat` and `Lia` prove the
natural-number arithmetic; `Unset Lia Cache` keeps `lia` from writing a
file.

|Lean leg
|`PROVEN`, route `re-proved`. `verification/proofs/lean4/Cohort.lean`,
Lean 4.29.0, core only. The gate's audit finds no axiom in any of the 95
theorems. No `simp`, `omega` or `ac_rfl`: each brings `propext` in.

|Statement correspondence (§2.2)
|Compared by reading, item by item. Each target restates every Agda
definition with the same constructors, fields and clauses, and states every
Agda theorem with the same hypotheses and conclusions (Agda `cash-identity`
is `cash_identity`, and so on). The differences are encoding only:

* Agda's `_<_` and `_-_` on Nat are `natLt` and `monus`, with the same
  clauses, recursive on the second argument as Agda's are, so that the
  same terms reduce.
* Lean compiles overlapping patterns with `propext`, so `meet`,
  `zipWith`, `kand` and `denominator` list their cases without overlap;
  `zipWith` and `kand` split their first argument first, as Agda's do.
  Each is the same function.
* Agda's `n div suc m` is `Nat.div` (Rocq) or `/` (Lean): each rounds
  down and gives 0 for a zero divisor.
* `T b` is `b = true`. The proof-relevant records `Covers`, `Bounded`
  and `Yes` are existential propositions, so every result is a theorem
  that the axiom audit inspects. `All` and `Any` stay functions on lists.
* The integers are Agda's (`pos`, `negsuc` and the same operations), not
  the standard `Z` or `Int`: Lean's `Int` lemmas use `propext`.

Residual assumptions: none in any leg.

|Machine receipt (§8.5.1)
|None yet. The receipt `verification/receipts/theory_praxis.deed` records
THY-1 only. Adding APP-1 to APP-4 needs receipts from a CI run on the merged
commit, so no grade is derived for them yet.
|===
